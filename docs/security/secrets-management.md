# Secrets Management & Rotation Policy

- **Date:** 2026-09-20
- **Owner:** Neurix engineering / ops
- **Status:** Mandatory reading before any production deploy or rotation.

## 1. Where secrets are allowed to live

| Location | Allowed? | Notes |
|---|---|---|
| `.env` on the server (chmod 600, gitignored) | ✅ | Generated by `scripts/setup-env.sh` |
| GitHub repo/action secrets (CI only) | ✅ | Currently `NVD_API_KEY` in security-scan.yml |
| `docker-compose.yml` | ⚠️ interpolation only | `${VAR:?}` references — never literal values |
| Java/Kotlin source, `application.yml` | ❌ | Defaults must be placeholders refused by `ProductionSecurityCheck` |
| Dockerfiles / images | ❌ | No `ENV SECRET=...`, no build-arg baking |
| Frontend bundle (`VITE_*`) | ❌ | Anything in the bundle is public by definition |
| Logs / audit records / error messages | ❌ | Passwords, tokens, reset links never logged |

## 2. Committed-secret incident (2026-08-10) — audit finding F-01

- Commit `b5a95f2` force-added `.env` containing `JWT_SECRET=local-dev-secret-please-rotate-me-…`
  and `APP_SEED_ADMIN_PASSWORD=admin123` (documented dev defaults).
- It was removed in commit `c03c6f7`, **but Git history still contains it**.
- **`.gitignore` does not make an exposed secret safe.** The exposure is permanent until the
  values are rotated anywhere they may have been used.

### Required actions

1. **JWT_SECRET** — rotate in every environment that has ever booted with the placeholder value.
   Anyone with repo access can forge admin JWTs for such an instance.
2. **APP_SEED_ADMIN_PASSWORD / APP_SEED_SUPERADMIN_PASSWORD** — rotate if any environment still
   uses `admin123` / `superadmin123` (also change the live account passwords, not just the env).
3. **GRAFANA_ADMIN_PASSWORD** — rotate if defaulted anywhere reachable.

### Boot-time guards already in place

- `ProductionSecurityCheck` (profile `docker`) refuses to boot on the known placeholder values,
  short JWT secrets, or wildcard/missing CORS.
- `JwtService` independently refuses blank/short/`please-rotate`-style secrets.

### Optional: history rewrite

`git filter-repo`/BFG can purge `.env` from history, followed by a force-push. **Trade-off:**
every clone/fork becomes stale and signed commits are invalidated. Rotation is the mandatory
remediation; history rewrite is hygiene, not protection.

## 3. Rotation procedures

### JWT_SECRET (logs out every active session — expected)
```bash
./scripts/setup-env.sh --force        # regenerates JWT_SECRET + seed passwords
sudo docker compose up -d --build
```

### DB_PASSWORD
```bash
sudo -u postgres psql -c "ALTER ROLE daleel WITH PASSWORD '<new-password>';"
DB_PASSWORD='<new-password>' ./scripts/setup-env.sh --force
sudo docker compose up -d
```

### Application account passwords
Follow `SECURITY.md` — prefer the in-app change-password flow; emergency path uses a locally
generated BCrypt hash so plaintext never enters shell history.

### Grafana
Update `GRAFANA_ADMIN_PASSWORD` in `.env`, restart the `grafana` service, sign in, verify.

## 5. Rules for new secrets

1. New integration (API token, SMTP, OAuth, Turnstile secret…) → add to `.env.example` with an
   empty/`CHANGE-ME` value and to `setup-env.sh` if it must be generated.
2. Never print secrets at INFO/DEBUG level; mask on failure paths.
3. Rotate on: personnel change, suspected leak, at minimum every 12 months for long-lived keys.
